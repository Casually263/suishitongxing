## 4. 每阶段执行规范

1. 读TASKS、相关需求ID和现有源码/变更，先保护已有工作；不反复重建正常模块。
2. 在进度记录中写本轮目标、涉及文件、接口/迁移变化、兼容性和退出条件。
3. 写真实文件；业务按钮必须有真实接口和状态流，未实现入口显式标识或不展示。
4. 执行适用编译/测试；修复本轮发现问题。依赖或权限受限时记录命令、失败原因、未覆盖范围，不假报成功。
5. 更新需求ID、TASKS和证据路径；所有适用退出条件通过才推进阶段。

后续测试记录格式：`日期/阶段/提交或文件范围/运行时版本/命令/退出码/结果/失败原因/未覆盖/证据`。缺少命令执行证据的功能最多标为“已编码，未验证”。

## 6. 四章内容制作门槛

每章至少包含：来源记录的中英知识卡、原创故事及素材授权、一个有效分支、一个可汇合双视角节点、一个可审核打卡、双方或明确标为AI的回礼、结局解释与印章。节点数量不以凑数为目标，所有可达路径须可结束，变量/奖励可解释。

立春作为第一条完整链；夏至、立秋、冬至使用同一引擎和schema，不能各写专用播放器。知识来源、地域差异、审校者和时间真实留痕。机器翻译可产生草稿，AI不能代替教师或留学生真实试读。
