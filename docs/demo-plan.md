# 岁时同行竞赛演示与验收计划

这是完整目标演示计划。当前阶段1身份基础和立春剧情闭环已可演示：真人双线索、刷新恢复、私有文字互动、结局印章。操作见[剧情说明](story-engine.md)。小满对话与无密钥脚本演示见[AI说明](ai-companion.md)。全年日历、公开审核、完整岁时册和编辑发布仍待实现，不能宣称完整16步已完成。没有真实推广成效或教师审校结论。

## 1. 主演示闭环

真实登录→数据库年度节气日历→立春篇章→中英知识卡→服务端剧情选择与刷新恢复→两真实账号不同线索→异步提交和统一判定→明确标为AI的小满对话/脚本降级→真实回礼与打卡提交审核→结局唯一盖章→岁时册→管理员图编辑、校对、发布→新会话读取新版→真实或标明演示的数据大屏。

## 2. 演示前置条件

- 可访问的后端、MySQL8、Redis7、MinIO和网站，正式部署HTTPS；保留服务日志与版本信息。
- 两个独立浏览器配置/设备：向导A中文、伙伴B英文；管理员单独配置；第三个无关账号C用于越权测试。
- 两个真实测试账号及有效真人结对；UI一直显示“演示账号/演示数据”。拟命名 demo_guide/demo_partner/demo_admin，但当前尚未创建。
- 已审核年度日期和四章内容；立春发布v1、可编辑草稿v2；既有存档固定v1。来源/素材授权/双语审校可查，不伪造教师签名。
- 上传文件使用自有示例图片、可公开的测试文本；不展示真人联系方式。
- 模型配置有“有key验证”和“无key脚本”两份运行证据；现场至少保证脚本完整可用，不能把脚本叫作已调用大模型。
- 演示 seed 在开发/演示库显式执行、可重跑不影响其他数据；重置需指定演示范围并核对库名，不自动删除生产库。

## 3. 十六步验收

| 步骤 | 操作 | 可见结果 | 真实数据/证据检查 |
| --- | --- | --- | --- |
| 1 | A/B分别登录网站 | 各自身份、语言、会话独立 | sys_user与有效JWT；密码/令牌不出现在录像 |
| 2 | 打开24节气日历 | 当期/下一项、倒计时、全年列表 | 修改演示年度日期配置后按规则生效，证明不在前端硬编码 |
| 3 | 选择立春篇章 | 已发布篇章、模式与来源 | chapter关联发布指针；其他筹备篇章明确标注 |
| 4 | 中/英/对照阅读知识卡 | 双语和来源、地域说明 | 只读已审knowledge_card版本 |
| 5 | 进入故事并阅读 | 插画/叙事/当前节点 | state返回当前节点，不返回整图或私有规则 |
| 6 | 做选择、退出、刷新重进 | 分支、变量与位置保留 | story_action与story_progress版本递增，重新请求无丢失 |
| 7 | 两人到达dual | 各显示专属视角 | 同session/version/checkpoint，slot固定 |
| 8 | 双机并排查看线索 | A看到clueA、B看到clueB | Network和安全测试证明单侧响应无另一侧线索/答案 |
| 9 | A先提交、稍后B提交 | A等待→双方统一揭晓、知识解释、默契变化 | WAITING落DB；B提交产生唯一JUDGED与奖励；刷新可重现 |
| 10 | 在已揭晓边界A切换小满并对话 | AI标识、中英引导、MODEL/SCRIPTED与降级提示 | 新上下文保留本人进度；provider/latency记录；不得传真人伙伴隐私 |
| 11 | 提交真实文字/图片回礼并完成必要打卡 | 待审→管理员通过→允许继续；展示双列或AI标识回礼 | 私有上传、审核记录与任务修订；公开需另行同意/精选 |
| 12 | 到达结局获得立春印章 | 结局解释、应时/补玩标识 | completion/stamp/reward唯一；重试不增加；未替缺席伙伴自动盖章 |
| 13 | 打开岁时册与分享海报 | 24位印章墙、1枚真实所得、徽章/年度进度 | 仅服务器完成记录；海报不默认披露伙伴私密信息 |
| 14 | 管理员打开VueFlow编辑草稿 | 拖拽/创建/连线/改双语、保存 | 保存graph可从DB重读；无效图给明确节点错误 |
| 15 | 校对审核并发布v2，使用新的测试会话 | 新会话读取改后文本；旧存档仍读v1 | 发布hash/审校留痕、immutable快照、新旧versionId证据 |
| 16 | 查看管理大屏 | 完成/结对/回礼/分享等有口径的指标 | real/demo分开、generatedAt、与stat_daily及原始事件对账，无虚构人数 |

用户“随时切换”的请求在正在等待的真人dual中应显示待处理状态及可用恢复方式，不能演示成无条件获知另一半线索。现场第10步安排在已判定边界，以真实安全规则完成切换。B仍保留自己的进度，可以独立完成本人内容；A的行为不能给B代领奖励。

## 4. 五分钟现场节奏

| 时间 | 展示重点 |
| --- | --- |
| 0:00–0:45 | 首页日历与双语知识，引出节气+故事+关系 |
| 0:45–2:10 | 双账号线索、第一人等待、第二人提交、解释与刷新恢复 |
| 2:10–2:50 | 小满对话与无key脚本模式；明确AI不判题 |
| 2:50–3:35 | 回礼/打卡审核、结局印章、岁时册与海报 |
| 3:35–4:35 | 管理图编辑保存、双语审校发布，新版读取和旧版兼容 |
| 4:35–5:00 | 真实数据口径与内容来源；已获得的真实试用反馈才可展示 |

五分钟展示可使用事先合法保存到checkpoint的演示存档，但必须说明预置进度；另提供从新账号开始的完整演示录像。48h超时通过可注入Clock的自动化测试或明确标注短窗口的测试剧情展示，不能篡改生产时间或假装真实等待48h。

## 5. 必须执行的负向与恢复验收

| 场景 | 预期 |
| --- | --- |
| C查询A/B的pair、session、messages、附件、AI历史；订阅其WS | 404/403，无隐私数据、无消息事件 |
| A在WAITING刷新或请求另一个nodeId | 状态仍等待；不能读B线索或未来节点 |
| 同requestId重复提交、换payload、换requestId重放旧节点 | 原结果/409；无第二次结算 |
| 双方同时提交、第二提交与超时任务竞态 | 恰好一次判定、一次奖励，存档一致；锁冲突可恢复 |
| 首答后到deadline恰好相等 | TIMEOUT；不能利用扫描延迟补交 |
| TIMEOUT延长后补交；AI替代后真人迟到 | 延长保留首答；替代轮封存；迟到不覆盖，需确认接受结果 |
| 等待期间切换AI问伙伴线索/正确答案 | 只见自己的允许上下文；不能获取未授权对侧线索 |
| 模型无key、8s超时、429、格式坏、审核不通过 | 自动脚本，mode和原因明确，存档不变、调用日志真实 |
| 伪装文件类型、过大图片、引用C的assetId | 拒绝；未审内容不公开，必要审核未过不发章 |
| 内容未经审校/批准后再修改/图有悬空边 | 发布失败，指出错误；已发布快照不变 |
| 用户被禁用、主动退出、解除关系后重用token/WS | 撤权生效，私密接口和订阅拒绝 |
| Redis断开、WS断开、后端重启 | 核心存档可恢复；模型保守降脚本；REST最终状态一致 |
| 新数据库部署与备份恢复 | 迁移成功、seed隔离、演示流程可重跑 |

## 6. 证据与参赛材料

阶段9在 `docs/testing/` 保存真实命令结果、日期/版本/环境、接口和并发报告、双语和布局核验、全链路录屏。演示用户事件和预览事件有标识，大屏不能把它们当真实推广成效。

材料包括：更新后的设计文档、源码和README、初始化SQL/示例脚本/Compose、接口文档、3–5分钟视频、12–15页PPT、内容与素材授权台账、测试报告和真实用户反馈。原文建议5位留学生+5位本地同学试用，这是待招募样本计划，未实施前不出现完成率/满意度或虚构原话。

现场备选：可用热点、数据库与对象快照、已核验脚本伙伴、离线演示视频。离线视频只能作为故障备份，不能把无法运行的现场系统宣称为可用。小程序展示依微信真实资质与开发/体验版状态明确说明。

## 可实际演示的编辑发布流程（2026-10-29）

管理员进入/admin/stories，使用“新建篇章”复制立春，命名为测试/演示数据。拖入节点、填写中英正文、连接真实分支，保存并校验；运行A/B隔离预览，确认不会领取真实印章。填写实际核对说明后发布，用新的普通账号打开/stories/{新篇章id}，验证刚才发布的节点和刷新存档。旧账号仍保留原版本。展示真实版本记录后归档测试篇章。不要把自动联调说明当作专家审校，不要覆盖正式立春以追求展示效果。详见[操作指南](story-editor.md)。
